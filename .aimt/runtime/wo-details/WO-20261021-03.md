## 1. 目的与背景

`I-038`：角色 Skill 里把项目契约文档写成**固定旧路径**（`docs/architecture.md` / `docs/llm-service.md` / `docs/cloudbase-integration.md` / `docs/app-onboarding.md` / `docs/brd-standard.md`），而消费端已按文档命名规范落盘为 `docs/03.tdd-*.md` / `spec-brd.md` 等 → 旧路径不存在，`guard sync-check` 永远指向一个 Skill 里根本没有的路径，同步提示成为噪音。

修法取 issue 建议的后半（不写死路径 + 门禁兼容新命名）：

1. 各角色 Skill 与 references 的文档指向改为**按 `project.json.docs` 绑定发现**的表述，只在必要处给示例文件名，不写成"必须存在"；
2. `surfaces-default.json` 的 `contractDocs` rules 增加新命名匹配（`docs/03.tdd-*.md`、`docs/spec-*.md` 等），并把旧 pattern 保留为兼容（存量项目仍用旧名）；
3. `docs/02-roles.md` 的角色-文档同步表同步口径。

**不做**：不动 `members/` 真源的角色职责语义（只允许其中的文档指代表述）。
