## 1. 目的与背景

三张 issue 同一根因族：**guard 的台账写入口与门禁口径不闭环**。

- `I-035`：`issues add` 落的草稿块只有抬头+来源行，没有正文占位；调用方"补正文"时若另追加同号块，文件里出现两块同号 I 编号，`normalize` 报"已规范"、`audit` 不告警，只能人眼发现（消费端 I-023/I-024 实证）。
- `I-036`：`surfaces-default.json` 的 T 面只含 `.aimt/runtime/**`，台账三件套 `.aimt/{issues,workorders,decisions}.md` 落 C2 → WO 内用 `guard issues add` 记账，收口 `check --wo --staged` 判越权（退出码 2）。guard 自己的写入口与自己的门禁互相打架。
- `I-037`：`issues add` 无写锁、取号非原子，两条并行命令都返回「已登记 I-0xx」且退出码 0，但只有一条落盘，另一条静默丢失。

## 2. 面域与路径白名单

## 3. 变更类型

`additive`（草稿块加占位行 / normalize 增同号重块检出 / T 面规则扩容 / issues add 加串行写锁），台账既有格式与编号空间不变。

## 4. 影响面

- 受影响 App / 服务 / 在线产物：全部消费端（0.7.2 副本）。`issues add` 输出多一行占位；`issues normalize` 可能新增非 0 退出路径；`.aimt/*.md` 面域从 C2 变 T（门禁放宽方向，不增加任何人的审批负担）。
- 需重部署：无（脚本随仓，下次同步生效）；行为变化须写进 release note。
