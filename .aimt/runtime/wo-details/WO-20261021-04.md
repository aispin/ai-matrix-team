## 1. 目的与背景

`I-039`：`expert-sync.mjs` 登记专家包时，账号归属由本机外部状态（`~/.workbuddy/settings.json` 的 `claw.legacyOwnerUid`）决定，只落到**一个**账号目录。多账号机器上第二个账号的专家中心"装了但看不见"，而 `--check` 只比对 marketplace/cache 两处，永远输出 OK，把漏登记掩盖成 UI bug。

修法（issue 建议 1+3，附加 2）：

1. **账号解析多账号遍历**：默认对 `~/.workbuddy/experts/custom/*/` 下每个已存在账号都登记；`--user <uid>` 指定单个，`--all-users` 显式声明（默认行为按遍历实现，`--single` 保留旧行为作逃生阀）；
2. **登记后回读校验**：写完全部账号后逐个读回 `experts.json`，缺该 id → 非 0 退出并指名账号；
3. **`--check` 加账号维度**：逐账号检查白名单是否含 `ai-matrix-team` + 两个独立包 id，缺失即漂移（退出码 1）并打印补登记命令；
4. 次级：源包 `settings.json` 被 watcher 清掉时，从 cache 自动补齐。

**调研要求**（10-research）：动手前先确认 App 侧读的是哪个文件、格式是否仅 id 数组（`ExpertPluginService.scanCustomExperts` → `readUserExpertIds`），以及官方 `register_expert.py` 是否支持指定账号；一手来源（App bundle 反查 / 脚本 --help）附在 journal。若官方脚本不支持指定账号，直接维护该 id 数组文件并回读校验——不得伪造 `storage/user-*/global/expert.json`。

**不做**：不删除任何账号目录、不清 `installed_plugins.json`、不改 marketplace.json 结构。
