# specs · 迭代规格文档库

> 本目录存放**每一次迭代**的规格文档：**需求 + 技术设计合一**，一份文档讲完整件事。


## 为什么合一

团队仓的迭代多为「小而有门禁」的改动，单独拆 BRD / PRD / TDD 三份文档会产生同步成本与漂移。
因此本目录采用**单文档规格（One-Doc Spec）**：一份文档自顶向下回答 Why → What → How → 如何验收。

## 命名与落盘

| 项 | 约定 |
|---|---|
| 文件名 | `SPEC-YYYYMMDD-NN-<slug>.md`（NN 为当日序号，slug 用小写连字符） |
| 位置 | `docs/specs/`（进行中）；完结后移入 `docs/specs/closed/` |
| 关联 | 头部必须写明关联 `WO-YYYYMMDD-NN-<slug>` 与 `DR-YYYYMMDD-NNN`（若需拍板） |

## 文档结构（模板骨架）

```text
1. 背景与目标        —— 为什么要做（Why），一句话可陈述的用户价值
2. 需求范围          —— 做什么 / 不做什么（What，含明确 out-of-scope）
3. 验收标准          —— 可机器判定的清单（AC，逐条可勾选）
4. 技术设计          —— 怎么做（How）：现状 → 方案 → 数据结构 → 影响面
5. 兼容与风险        —— 破坏性自查、降级路径、回滚
6. 验证命令          —— 可复制直跑的命令 + 期望结果（须实跑过）
7. 待拍板（可选）    —— 需创始人裁决的选型，逐项给选项/代价/推荐默认值
8. 关联              —— WO / DR / 既有规范文档
```

> 首次落地的完整样例见 [`SPEC-20261008-01-multi-harness-adapter.md`](SPEC-20261008-01-multi-harness-adapter.md)。

## 附：照抄清单 · 如何接一个新 Agent 运行环境（harness）

> harness = Agent 运行环境（成员实际干活的工具，如 WorkBuddy / codex / claude code）。
> 样板实现：`dashboard/server/harness/codex.mjs` 与 `claude-code.mjs`。
> 改动面上限：**1 个新增文件 + 1 行登记**（越出此面需回资深风控师核准扩单）。

| 步骤 | 动作 | 口径（四处必须一致） |
|---|---|---|
| 1 | 定环境标识 `<id>` | 正则 `^[a-z0-9][a-z0-9-]{0,31}$`（小写字母/数字/连字符，首位不为连字符，长度 1–32）。非法 id 事前拒绝，不进加载环节 |
| 2 | 新增 `dashboard/server/harness/<id>.mjs` | **文件名** = `<id>.mjs`；导出 `{ id, label, instances() }`：`label` 非空且不与「WorkBuddy」「通用（仅登记表）」重名；`instances()` 同步、fail-soft（异常返回 `[]`）、绝不抛错 |
| 3 | 登记条目写字段 | **登记表字段名**固定为 `harness`，值 = `<id>`；缺该字段的条目按 `workbuddy` 计（历史数据不必回补） |
| 4 | 选择它 | `project.json` 的 `harness.id`，或环境变量 `AIMATRIX_HARNESS`（优先级：前者 > 后者 > 缺省 `workbuddy`） |
| 5 | 失败怎么走 | **降级方式**（两级，不要混为一谈）：① **环境解析层**——id 非法 / 文件不存在 / 契约不符 → 静默落 `generic`（通用兜底视图，只读登记表、展示全部条目）；② **数据读取层**——登记表缺失 / 坏 JSON / 顶层非数组 → 实例列表为空数组 `[]`，**环境标识不变**（仍是你选的那个环境，不会因此退回 `generic`）。两层都不抛异常 |
| 6 | 注销 | 删掉 `<id>.mjs` 即自动回兜底视图，不用改任何清单文件（约定即注册） |

## 纪律

1. **先文档后编码**：spec 经创始人（或 DR 核准）签字后才进入编码，禁止边写边做。
2. **需求由产品设计主笔、技术设计由研发主笔**，主理人（PC）合稿并核术语（章程 T4：禁止裸用缩写）。
3. 规格变更直接更新到最新状态（历史沿革由 git 管理，文档不保留迭代记录）。
4. 文档是当次迭代的唯一设计真相源；与代码冲突时以文档为准并回写代码。
