## 0. 一句话

让每一张 WO/DR 单**一眼看出是谁、在哪个模块、要老板干什么**；让老板**不点开细节就能拍板**。

## 1. 背景与问题

专家团运行 2 天产出了 30+ WO、18+ DR，暴露三个结构性痛点：

1. **溯源缺失**：单据上没有「来自哪个会话」「属于哪个模块」的直接标识。出问题时（如 10-06 的并行撞车、DR 归档成批移动）无法快速按会话/模块归因和过滤。
2. **单据过重**：DR 的受众是老板（不懂技术细节），但实际落单时 9 节结构 + 字段表 + 技术化选项表把「要我做什么」淹没在细节里（实例：DR-20261006-001 的选项表含配音机时、ICP 备案等执行层措辞）。WO 虽以执行角色为受众，但收口勾项、执行记录的写法自由度大、粒度不一。
3. **清单不可分组**：dashboard 的 WO/DR 清单是平铺列表，老板无法按「模块」（dashboard / lucia / cruru / guard 工具…）或「会话」聚合查看；DR 清单只显示一句话，看不到选项与推荐项。

## 2. 目标用户与场景

| 用户 | 场景 |
|---|---|
| **老板（主要）** | 打开 dashboard → 3 秒知道「现在有几件事等我拍板、各属于哪个模块、推荐是什么」→ 逐项拍板，不读技术细节 |
| 主理人/成员 | 出问题时按会话/模块过滤单据归因；写单时少纠结格式 |
| 执行角色 | WO 信息密度不降低，执行不受影响（硬约束） |

## 3. 目标与非目标

**目标**
- G1 每张 WO/DR 可按「模块」和「会话」两个维度识别与过滤（归因 ≤5 秒）。
- G2 老板不点开任何细节，仅凭 DR 卡片/摘要即可完成拍板。
- G3 dashboard 清单支持按模块分组（默认）与按会话分组（切换）。
- G4 单据简化不降低执行正确性（WO 的白名单/验证/回滚三要素零削减）。

**非目标**
- 不改 DR/WO 的编号体系、决策协议（04-decision-protocol）与锁机制。
- 不做单据系统迁移（仍是 markdown 文件 + LEDGER 索引）。
- 不在本版做 dashboard 的权限/多用户。

## 4. 需求列表

### P0-1 单据溯源字段（痛点 1）

**R1.1 `模块` 字段 = 自动派生，禁止手工**
- WO：由 §2 白名单 paths 推导（`.skills/dashboard/**`→`dashboard`；`apps/lucia/**`→`lucia`；`.skills/scripts/**`→`guard-scripts`；`apps/cruru/**`→`cruru`；其余→`infra/docs`）。推导逻辑进 `guard parseWo`，渲染层统一消费。
- DR：由「所属」字段推导（`WO-xxx`→该 WO 的模块；`App: xxx`→`xxx`；`契约: xxx`→`contract`）。
- 验收：`guard wo lint` / `dr lint`（新增）对 100% 存量单输出模块标签无歧义；歧义单（白名单跨模块）标 `multi:<模块列表>`。

**R1.2 `会话` 字段 = 落单时固化**
- DR 字段表、WO 字段表各增一行 `会话`：值 = 落单时提出者当前 `角色#呼号 · 会话名`（从 instances.json 取；离线时手写）。
- lint 规则：OPEN 单缺 `会话` → P3 告警（不阻断，存量单豁免）。
- 未来（P2）：harness spawn 时自动注入，见 §7。

**R1.3 存量单回填**
- 一次性脚本为存量单补 `模块`（派生）+ `会话`（能从 instances.json/LEDGER 关联的回填，关联不到标 `unknown`）。

### P0-2 DR 老板视图（痛点 2）

**R2.1 模板加「§0 摘要卡」，四要素 + 硬性字数纪律：**

```markdown
## 0. 给老板的摘要（四行内拍板）

- **背景**：≤80 字，零术语（技术名词必须带 5 字以内人话解释）。
- **你要选**：A = ____ ／ B = ____（每项 ≤40 字，只说后果不谈实现）。
- **我的推荐**：选 __ ，因为 ____（≤30 字）。
- **不拍板的后果**：____ 等到 ______（日期）；BLOCKING 则相关工作停摆。
```

- 原 §1–§9 全部保留，整体定位为「执行细节」，供执行角色与归档审计用。
- lint 强制：§0 四要素齐备、字数上限、背景段无未解释术语（术语表来自 `config.json.terms`）→ 违反 exit 5。

**R2.2 渲染端默认只出摘要卡**
- dashboard DR 抽屉、aimatrix-report 的「④ 需要您定的事」：有 §0 的 DR 只渲染 §0 + 「展开细节」入口（markdown details 或抽屉二级页）。
- 无 §0 的存量 DR：渲染层从 §1/§3/§4/§5 自动合成降级视图（合并 PRD 阶段实现，合成失败退回现状）。

**R2.3 WO 简化（三处，不动骨架）**
- 字段表后加 `## 0. TL;DR`：做什么 / 为什么 / 怎么算完成，各一行。
- §10 收口勾项模板预置标准清单（QA/契约/交接单/锁/归档五项固定），单据只填差异项。
- §9 执行记录由表格制改**追加式 bullet**（`- [时间] 谁：做了什么 → 结果`），降低书写负担。
- 硬约束：§2 白名单、§5 验证方式、§6 回滚的字段格式零改动（guard lint 既有校验不变）。

### P0-3 dashboard 分组与老板视图（痛点 3）

**R3.1 数据层**
- `/api/pipeline` 的 WO/DR 条目增补 `module`、`session` 字段（服务端派生，见 R1.1/R1.2）。
- **顺带修复**：server.mjs `decisions()` 仍读 LEDGER（与已修复的 report.mjs D3 同源缺陷）→ 改为实时扫 `decisions/open/`。

**R3.2 前端**
- 管线页清单默认**按模块分组**（组头：模块名 + 在办数/待拍板数），组内按状态排序。
- 顶部切换：「按模块」（默认）/「按会话」（仅显示有会话字段的单，unknown 归「历史单」组）。
- DR 卡片渲染 §0 摘要卡四要素；OPEN 的 BLOCKING 卡片置顶并红框。

**R3.3 报告（图形版）**
- SVG 汇报「④ 等您拍板」区加模块标签 chip。

### P1（下下轮）

- `guard dr lint` 独立子命令 + `ledger-sync` 消费 §0 摘要。
- 按会话的归因报表（哪次会话产出/关闭了多少单）。

### P2（远期）

## 5. 验收标准（可观测）

| # | 标准 |
|---|---|
| AC1 | 任取一张新落 DR，老板只读 §0 即能复述「背景/选项/推荐/后果」四要素（走查 3 单） |
| AC2 | dashboard 管线页 WO 与 DR 清单均按模块分组展示，组数 = 存量模块数，无「未分组」孤项 |
| AC3 | 切「按会话」视图后，每张本轮新落的单都出现在其会话组内 |
| AC4 | `guard wo lint` 对缺 §0/超字数的 DR 样单 exit 5；对全部存量单不回归（WO-10 修复的 handoff 校验同步验证） |
| AC5 | WO 执行角色走查：TL;DR 与勾项模板上线后，`guard check`/锁流程/交接单校验全部不受影响 |
| AC6 | server `/api/pipeline` 返回的 open DR 集合 = `decisions/open/` 实时目录内容（含并发新落单） |

## 6. 方案取舍记录

| 取舍点 | 选项 | 结论 | 理由 |
|---|---|---|---|
| 模块标识 | A 手工填写 / B 自动派生 | **B** | 白名单本就是唯一真相源，手工必然漂移 |
| 会话标识 | A 只在 instances.json 查 / B 落单固化 | **B** | instances.json 是易失状态，会话结束即失联 |
| DR 简化 | A 砍掉技术节 / B 加摘要卡分层 | **B** | 细节是执行与审计的依据，删了伤正确性；分层兼顾两类受众 |
| 分组默认维度 | A 会话 / B 模块 | **B** | 模块稳定、老板心智模型匹配；会话生命周期短作次级视图 |
| 存量单 | A 不动 / B 回填 | **B（脚本一次性）** | 不回填则分组视图出现大「unknown」组，功能形同虚设 |

## 9. 与现行机制的关系

- 本 PRD 全部改动为 **additive**：不改决策协议、锁、编号、归档流程。
- 昨晚 WO-10/12 修复的 guard 能力（lint handoff、归一化比对）是本 PRD lint 规则的前置，已在位。
- 模板属 C2 受控面、dashboard 属 C2：实施时照常走 WO + 锁 + QA。
