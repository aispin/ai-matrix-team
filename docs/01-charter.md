## 1. 定位

**AI Matrix Team** = ai-matrix 仓库内的**软件产品开发组织**。成员是 AI Agent（员工），创始人是唯一人类（缔造者）。

- **对内**：把「多个 AI Agent 各干各的」变成「一条有门禁的交付流水线」。
- **对外**：保证每款 App（moozi / cruru / lucia / boduo / …）在**共享资产不被污染**的前提下快速上线。
- **不做什么**：
  - ❌ 不替代既有工程文档（`architecture.md` / `shared-contracts.md` / `brd-standard.md` 仍是各自领域的唯一真相源，本团队只做**执行与守门**）。
  - ❌ 不引入 PR 审批流——一人公司 + Agent，流程要轻；靠**机器门禁**而不是人工签字。
  - ❌ 不为对齐而重写存量文档（既有约定）。

## 2. 五条治理原则

| # | 原则 | 含义 | 违反的典型表现 |
|---|---|---|---|
| **P1** | **机器优先于文档** | 每条纪律都要有脚本/门禁/台账兜底；只写在文档里的纪律等于不存在 | 「shared-contracts 说要登记，但没人登记也没人发现」 |
| **P2** | **单一真相源** | 面域清单、契约台账、决策台账各只有一处；别处只做引用或由它生成 | 三份文档各写一份权限矩阵，改一处漏两处 |
| **P3** | **最小惊讶** | 任何 Agent 的写入都可预告：有 WO、有锁、有登记。别人读到仓库时能看到「谁在改什么」 | 某天发现 `packages/shared-types` 被改了，无人知晓 |
| **P4** | **默认可逆** | 破坏性变更先 INTENT、先兼容证明、先回滚方案；Type 1 决策不允许「沉默通过」 | 改了 `AppId` 联合类型才发现线上服务行为变了 |
| **P5** | **人只做只有人能做的事** | 拍板不可逆承诺、提供凭据/资金/账号、定优先级。其余一律由 Agent 带建议默认值推进 | Agent 反复问「要不要用 Tailwind」这类可自决问题 |

## 3. 角色与责任矩阵（RACI）

图例：**R** 执行 · **A** 最终负责（可被打回） · **C** 必须被咨询 · **I** 事后知会 · **—** 不参与

| 关键动作 | PC | 毛毛 | Bruce | 石头 | 波波 | 创始人 |
|---|---|---|---|---|---|---|
| 立项论证（BRD） | A | R | C | — | — | **拍 Type 1 / Go-No-Go** |
| PRD 与验收标准 | A | R | C | C | — | I |
| 可交互视觉稿（设计） | A | **R** | C | C | — | **拍品牌色等 Type 1 视觉口径** |
| TDD / ADR / 技术选型（架构速断） | A | — | R | — | C | **拍跨 App 选型** |
| 写 `apps/<app>/**`（自由面） | A | C（出稿） | R | C | — | — |
| 写 `packages/*`（受控面） | **A（守门）** | — | R（白名单内） | C | — | — |
| 写 `services/*`（受控面） | **A（守门）** | — | R（白名单内） | C | C | — |
| 写根 `docs/**`（受控面 **C2**） | **A（守门）** | C | C | I | I | — |
| 共享面契约登记 | **A / R** | — | C | — | — | — |
| 串行锁的持有与释放 | **R** | — | C | — | — | — |
| 全矩阵 typecheck/test/build 门禁 | C | — | R（修复） | **R（判定）** | — | — |
| **定期合规巡检（全矩阵）** | A | C | C | **R（独立执行）** | C | **看报告 / 拍整改优先级** |
| 部署 / 迁移 / CORS / 回滚 | A | — | C | C | R | **给凭据/执行授权** |
| 待决策项（DR）提出 | **A（台账）** | R | R | R | R | — |
| 待决策项（DR）答复 | — | — | — | — | — | **R** |
| 交付汇编与交接单 | R | I | I | I | I | I |

> **读法**：凡受控面写入，**团长（PC）是守门人（A）**——他不是「写得最多的人」，而是「对写入合法性负责的人」；实际代码由Bruce在 WO 授权范围内执行（R）。例外清单场景（破坏性/新契约/Type 1/多单锁冲突/利益相关）团长提请创始人裁定（charter §4A.3）。
> **为什么巡检归石头**：资深质检工程师不写业务代码、不核准 WO、不持共享锁——是团队里唯一**手上没有可被自己审计的权力**的裁决型角色。让团长（自己也核准受控面）或Bruce（自己出的设计）来巡检，会变成「自己查自己」。

## 4. 协作铁律（沿用 WorkBuddy Team 规范 + 本项目特化）

### 4.1 通用铁律（不可简化）

1. **团队只能由主理人创建**（TeamCreate），严禁委派成员建团队。
2. **按 SOP 阶段调度成员**，成员作为独立协作方输出专业产出；**主理人不得代写任何成员的专业产出**。
3. **所有跨成员信息流经主理人中转**，禁止成员互相直连。
4. **成员结论为准**：专业结论必须由对应成员输出后再采信，主理人只做编排与汇编。
5. 调度时 `Agent` 工具的 `name` 与 `subagent_type` 均传 **Agent ID**（MD 文件名，不含 `.md`），禁止用中文名。

### 4.2 ai-matrix 特化三条（新加）

| # | 铁律 | 落地物 |
|---|---|---|
| **T1** | **无 WO 不动受控面**：改 `packages/*`、`services/*`、根 `docs/**`、`infra/`、`scripts/`、`matrix.config.schema.json` 之前必须有活跃 WO，且共享面锁在手 | `aimatrix-guard check` 退出码 2/3 |
| **T2** | **BLOCKING DR 不闭环不推进**：当前任务关联的 Type 1 / BLOCKING 决策未获人类答复，不得进入下一阶段（绝不靠沉默默认通过） | `aimatrix-guard dr scan --blocking` 退出码 4 |
| **T3** | **交付必有交接单**：任何 WO 收尾都要产出 `<project>/.ai-matrix-team/runtime/handoffs/WO-xxx-handoff.md`（改了什么 / 怎么验证 / 怎么回滚 / 遗留 DR） | 主理人收口时检查 |
| **T4** | **禁止裸用缩写术语**：一切对外/跨人交付物（BRD/PRD/TDD/设计稿/评审报告/交接单/汇报）禁止使用未经释义的行业缩写（如 KYB、KYC、OTP、SLA）；确需使用（含字段名、单据号、UI 文案）时，**必须在文档头部附「术语缩写释义表」**（缩写 | 全称 | 中文释义，至少覆盖全文出现的每一个缩写）。本团队内部标准缩写（WO/DR/AC/TDD 等，见 §6 术语表）除外 | PC 派单时把关 + 石头巡检抽查 |

### 4.3 严禁行为

- ❌ 跳过 TeamCreate 直接自己模拟多角色发言
- ❌ 主理人代写 BRD/PRD/TDD/代码/验收结论
- ❌ 未完成前序阶段就跳到后续阶段（尤其：BRD 未过 → 不许开工）
- ❌ 「顺手改一下共享面」——没有 WO 的受控面改动，无论多小
- ❌ 把未验证假设写成结论（沿用 `brd-standard.md` C7）
- ❌ 交付物里裸用行业缩写（KYB 之类）——要么写全称，要么文档头部附释义表（T4）

## 4A. Express 运行模式

**默认 Express（轻装），例外 Full Convoy（重装编队）。**

1. **模式切换**：默认 Express——零 spawn、QA 走 L0–L2 分级、风控团长兼任。命中任一 → 该单升级 Full Convoy（独立 QA spawn；风控裁定升级为**团长提请创始人裁定**）：破坏性变更 / 新契约 / Type 1 不可逆 / 上线发布 / 核心共享包（C1）。单内升级，收口后自动回落。
2. **Spawn 基准**：四判据（① 需要第二双眼睛 ② 长时/真机任务 >10min ③ 上下文隔离收益 ④ 真并行收益）**命中 ≥2 才 spawn**；并发 ≤2；prompt 只引路径（≤600 字目标）；子代理连败 2 次降级主会话代行；spawn 次数记入 WO §9。
3. **风控合并**：风控席位已物理删除，核准权**团长全收**——C1/C2 写入核准、共享锁、契约登记、破坏性升级裁定；guard CLI 机器门禁留痕 WO §9。例外清单（团长提请创始人裁定）：扩大白名单 / 破坏性或新契约 / Type 1 / 多单锁冲突 / 团长为利益相关方。事后抽检兜底（retro 或创始人巡检）。测试承接「破坏性影响面核对」作为 QA 清单核对项（只核对、不裁量，保独立审计）。
4. **QA 分级**：L0 文档/流程产物=团长自检；L1 非受控小迭代=机器门禁+复核；L2 受控面常规=机器门禁+复核+**留痕待抽检**；L3=Full Convoy 独立 QA。抽检出问题该类单强制升级 L3。
5. **会话卫生**：一会话一 WO，收口即归档开新会话；每日日志按单据拆分（`.workbuddy/memory/<date>/<slug>.md`），日志主体只留索引；Read 带 offset/limit、禁止整读大文件；MEMORY.md 只放铁律。
6. **输出纪律（Ponytail 阶梯，lite）**：代码执行类 WO 落笔前依次过——跳过 → 复用现有代码 → 标准库 → 语言原生 → 已装依赖 → 最后写最少新代码；**验证/安全/可访问性永不在裁剪清单**。开关：项目薄层 `project.json` 的 `outputDiscipline.ponytail`（默认 true，false 时本条不生效）。
7. **汇报纪律**：汇报只在**较大特性 / 里程碑收口**时生成（多单闭环、发布、架构级变更、编制调整）；Express 小迭代收口**不生成汇报**——一句话结论写进交接单即可。同一天多条汇报视为违规，主动合并。
8. **单据字节纪律**：WO 主文件 ≤6KB 硬上限（超限风控打回）；§9 执行记录等过程叙事一律走 `WO-xxx.journal.md` append-only（`guard wo journal --wo <id> --who <角色#呼号> --what "…"` 机器追加；LLM 只发增量条目、禁整读旧文）；交接单/汇报回执 ≤15 行（结论行 + 证据指针，不贴过程）；`runtime/reviews/` 单篇 ≤200 行。存量单据不回填迁移（新单新办法）。`guard stats` 持续度量单据字节。

## 5. 与既有文档的关系（边界）

| 既有文档 | 它管什么 | 本团队怎么用 |
|---|---|---|
| `docs/architecture.md` | 架构与数据模型 | Bruce的输入与约束；改动需 ADR |
| `docs/shared-contracts.md` | **共享面清单 + 变更日志（事实登记表）** | 团长（守门人）的登记落点；本团队提供「登记前的闸门」 |
| `docs/brd-standard.md` | BRD 写作规范 | 毛毛的执行标准 |
| `docs/app-onboarding.md` | 接入部署 SOP | 波波的执行标准 |
| `docs/decisions/ADR-*` | **已决策**记录 | DR 答复后的归档去向之一 |
| `apps/<app>/docs/OPEN-ITEMS.md` | 面向人的叙述式待办清单 | 由 DR 台账驱动，必须交叉引用 DR id（见 [`04`](04-decision-protocol.md) §7） |

> **核心区分**：`docs/decisions/ADR-*` = **已决策**（过去时）；`decisions/DR-*` = **待决策**（现在时，等人类）。两者不许混用。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| **面域（Surface）** | 仓库路径的管控分级：C1/C2/C3 受控面、F 自由面、T 台账面 |
| **WO（Work Order）** | 任务单。受控面写入的准入凭证，含影响面、验证方式、回滚方案 |
| **DR（Decision Request）** | 待人类决策项。BLOCKING 会阻塞流程，NON-BLOCKING 带默认值可先跑 |
| **锁（Shared Lock）** | 共享面写锁，落实「串行优先」；**按面域分片**——面域不相交的多个 WO 可同时持锁，同面域仍互斥 |
| **INTENT** | 破坏性变更的**事前**预登记（动手前登记，注明影响面与验证方式） |
| **门禁（Gate）** | 阶段之间的硬检查点，由 `aimatrix-guard` 或资深质检工程师执行，不通过不得推进 |
| **交接单（Handoff）** | WO 收尾产物：改动清单 + 验证证据 + 回滚方式 + 遗留 DR |
| **Type 1 / Type 2** | 不可逆 / 可逆决策（沿用 `brd-standard.md` §11） |
