## 1. 需求摘要（闸门 1 · **Hugo 已确认**）

1. **用户**：创始人（单人使用、本地面板 `127.0.0.1:4780`，桌面为主，也要窄屏可用）。
2. **核心任务**：一眼看清「谁在干什么 / 哪里卡住 / 什么办结了 / 有什么等我拍板」。
3. **数据**：`<project>/.ai-matrix-team/runtime/` 台账（工单 / 待拍板 / 成员 / 占用）+ `data/dashboard.db` 汇报库，经 `server/server.mjs` 的**只读端点**。
4. **约束**：**不新增、不修改任何端点与数据结构**；不碰 `server/**`、`data/**`、`package.json`；本 Phase 产出**全部是新增文件**；单文件零依赖；375px 无横向滚动。
5. **现状痛点**：导航/删除/状态全是 **emoji 当图标**；多层工单叠加导致**层级靠颜色堆叠**、圆角/间距/阴影失控、**缺状态兜底**（空/加载/错误）；这个面板**从无设计稿**。
6. **成功定义**：创始人不再说「丑」——有设计感、层级清晰、状态兜底齐全、**浅深双主题都成立**、**零 emoji 图标**。
7. **平台假设**：Web 桌面优先（默认断点 1080 / 720），窄屏折叠侧栏为顶栏。

### 2.1 一个刻意做出的结构性调整（规避 Bruce 备忘 §2.2 的「右上角三向重叠」）

现状：汇报页「图/文切换」`fixed` 右上（`.view-toggle`）、灯箱工具条 `fixed` 右上（`.lightbox-tools`）、拟新增的主题切换按钮——三处都在右上，会打架。
**本稿方案**：把「图/文/全屏」从 `fixed` 右上**收进内容区页头右侧**，与**主题切换按钮**同处一行（各自带标签）；灯箱工具条仍是独立浮层（仅灯箱打开时出现，不冲突）。**主题切换**放两处按断点择一：桌面在**侧栏底部「外观」行**，窄屏随侧栏折成顶栏后仍在可达位置。落码时按 Bruce §2.2 定的坐标实现。

## 4. 关键设计决策

1. **色彩方向：创始人 2026-10-06 验收定案 = 候选 B「冷静灰」（中性冷灰底座 + 暖橙**仅作品牌点**）。** 诊断：「丑」的根因经比对**主要在执行层**——不是色相本身，而是 ① 主色滥用（橙色标题 + 橙 nav + 橙按钮 + 橙 chip 铺满一屏，主色占比远超 10%）；② 圆角 14/12/10/9/8 混用、间距出现 6/7/10、阴影单层；③ 缺状态兜底；④ emoji 图标。**故主稿底座转中性冷灰（浅 `#F3F5F9→#E4E8F0`）；暖橙收敛为品牌点**；视觉稿保留色板对比开关（**初始态 = 冷静灰**，暖夜灯降为对比项）。决策正文与留痕见 §6。
2. **层级改用「三把刀」（尺寸 > 字重 > 明度），不再靠颜色堆。** 区块标题由现状的**橙色粗体**改为**中性色 600 字重**（`--text`）；主色 `--accent` 收敛到只用于：选中态、主按钮、焦点环、主张强调点——**单屏主色面积 < 10%**（本轮又删去侧栏品牌橙竖条，主色占比再降）。
3. **状态标签一律「点 + 文字」**（`● 2 人施工中` / `● 无待拍板事项`），不只靠颜色；色盲用户、黑白打印稿均可读。阻塞级「待拍板」用**实心危险色 chip**做唯一最强权重。
4. **栅格/圆角/阴影令牌化，全部落 8pt 栅格。** 圆角收敛为 **8 / 12 / 16 / 999** 四档（同层级只用一种）；**卡片静态只留 1px 边框**（§7），阴影只给 hover 抬起 / 浮层且**双层叠加**（近硬边 + 远柔边，§2.4）；数字一律 `tabular-nums`（计数/时间/百分比不抖动）。
5. **图标全部自绘 SVG 替换 emoji**：`24×24` 网格、`stroke-width:1.5` 全套统一、`stroke="currentColor"`、圆头圆角、`aria-hidden`，纯图标按钮带 `aria-label`。覆盖 Bruce §2.2 列出的**全部 15 处** emoji/文字符号（导航 ×3、告警/暂停/完成、删除、关闭、缩放 −/＋、重置、图形/文字、全屏）。
6. **双主题三件套一次给全**：`<head>` 内联防闪脚本 + `[data-theme]` 手动切换 + `localStorage` 记忆 + `@media (prefers-color-scheme)` 跟随系统；`color-scheme` 让滚动条/原生控件跟随；深色下**零硬编码色**（全部走令牌/`currentColor`），语义色改「浅字 + 半透明底」。
7. **深色品牌色单独指定，不用公式推导**（暖橙属红橙黄棕系，`design-system §2.6 规则 9`）：浅色 `--accent:#EA580C`，深色**显式**给 `--accent:#FB923C` / `--accent-deep:#FDBA74`（在冷灰深底上提亮一档，保证深字对比 ≥4.5:1；原 `#F59E0B/#FBBF24` 为暖底取值，随底座一并调整）。
8. **汇报「图/文切换」由 fixed 右上改为页头内联**（见 §2.1），一并解决主题切换按钮的落位与三向重叠。
9. **动效克制 ≤180ms / ease-out**，全部在 `prefers-reduced-motion: reduce` 下静态降级（骨架屏 shimmer 停动）。
10. **侧栏品牌区移除橙色竖条**（创始人 2026-10-06 反馈）：「左边栏顶部的 LOGO 区，不需要左边的橙色边框」。删去 `.brand-bar`（两稿的 CSS + 两处标记——侧栏品牌区与抽屉头），改用**字号 15 / 字重 700 / 字距 -.01em** 做**中性**锚点；不复活橙色竖条。`--accent-deep` 变量**保留**（稿内仍有 `nav 选中文字`/`md h2`/`SVG 图形版` 三处引用，非悬空）。

## 6. 色彩方向（Type 1）· **已定案：候选 B「冷静灰」**

> **结论回填（DR-20261006-006 · 结论落这里）**
> 创始人 **2026-10-06** 验收本稿时对色彩口径拍板 —— **采纳候选 B「冷静灰」**。原话留痕：
> > 「色彩用冷静灰；左边栏顶部的LOGO区，不需要左边的橙色边框。其他没问题。」

> **整改缘起（emoji 子例 vs WO §5 门禁）**：§6.5 要求「06 超长内容」必含 emoji，而 WO §5 的机器门禁为源码级 `! grep -qE '[1F300-1FAFF 2600-27BF]'`（对任何 emoji 码点一律判否）。二者以「**渲染为 emoji、源码不含码点**」的方式同时满足：该处 emoji 用 HTML 数字字符引用书写。门禁语义仍是「无 emoji **当图标**」（§3.1 明确内容中的 emoji 属例外，与 `examples/05 L325`「🎉 上线庆祝活动策划案 v2 🚀」同旨）。

> **本轮（v2）缘起 —— 创始人验收反馈两项**（2026-10-06 验收，原话「其他没问题」）：
